# 維護注意：Redmine 工單時代的條目（2026-11-17 自 docs/maintenance.md 移出）

這些條目描述的模組（`redmine.py`、`scan.py`、`status.py`、`reopen.py`、`landed.py`、`login.py`、cake73 站點 driver）已移到 `legacy/redmine/python/`，不再是現行程式。

- 多角色（`/dispatch`）：角色只靠 `worktrees/<工單>/_ticket/` 的檔案交接；`status.json` 只能用 `bin/console status --set` 寫。嚴重度條件改在 `docs/agent-protocol.md` 一處，不要複製進各角色檔。專案端技能（speckit、code-review）在 console 這邊不會自動載入，角色是 Read 它們的 `SKILL.md` 當程序依據。spec 閘門與專案端「停下等確認」見協議；專案端第 5 節目前是**試行中的放寬**（審議團放行時不停下，備份在 `docs/project-skill-redmine-ticket.SKILL.md.bak-*`，還原就是把備份蓋回樣板；已建好的 worktree 內有舊副本，樣板只影響之後新建的 worktree）。改之前先看樣板第 3、5、7 節。
  - **spec 由專案管理員寫（2026-11-16 新增）**：原本 spec 閘門只能請使用者換視窗跑專案端 `/redmine-ticket`，裁決改向（人工裁示）後舊 spec 與裁決相反也卡在那裡。現在 dispatch 閘門在「spec 不存在」或「`decision.md` 比 `consistency.md` 新」時派 `ticket-manager` 的 `spec` 模式，它 Read worktree 內專案端技能與 speckit-specify 的 `SKILL.md` 當依據（子代理人沒有 Skill 工具）、以 decision 為準修訂 `spec.md`、每次都寫 `consistency.md`（兼當時間戳）；有無法消除的衝突就回報 `放行: 否`，由 dispatch 升級。寫檔被拒時比照 `summary.md`：附內容由 dispatch 原文代寫、不繞過。工程師仍不得改 `specs/**`。使用者親自在專案端視窗處理 spec 的路徑照舊可用。備份：`docs/agent-protocol.md.bak-202611161720`、`.claude/agents/ticket-manager.md.bak-202611161720`、`.claude/skills/dispatch/SKILL.md.bak-202611161720`、`docs/maintenance.md.bak-202611161720`。尚未實測：子代理人能否寫 worktree 內 `specs/`，以及 `ticket-manager` 用 sonnet 改 spec 的品質；第一次用（工單 3568）後視結果調整。
- 專案端技能（`templates/project-skill/redmine-ticket/SKILL.md`）是由 `docs/legacy-redmine-ticket-SKILL.md` 拆出的後半；原文若更新，兩邊要一起看。
- 分析階段的成本控制（2026-11-16 調整，原因是 4 張工單同時跑時 5 小時額度被耗盡）：①`ticket-analyst` 加了查碼預算（lens 15、rebut 5、decide 8 次工具呼叫；回覆多一行 `工具呼叫：<實際>／<預算>`，日後用它檢視預算是否合適）；②dispatch 2b 的跳過辯論條件放寬：不再要求三位結論一致，只看 `severity` 都不是高、`hit_rules` 皆空、沒有 `needs_clarification`，分歧交給 decide 逐一查驗，無法化解就判低信心並升級；③`CLAUDE.md` 的維護注意搬到本檔。備份：`.claude/agents/ticket-analyst.md.bak-202611161432`、`.claude/skills/dispatch/SKILL.md.bak-202611161432`、`CLAUDE.md.bak-202611161432`，還原就是蓋回去。預算是否太緊，看之後各角色最後回覆的工具呼叫次數與裁決品質再調。
- 已併入偵測（`landed.py`、`bin/console landed`）：重派的工單成果可能早已在 base 上，原流程不知道所以整套重跑、抓不到重點。console 只收集證據（分支是否已併入／patch 等價、base 上提到工單號的提交數、檔名、最新時間）寫 `_ticket/landed-<專案>.json`；**絕不取提交主旨**（可能夾帶客戶名稱，只用 `--format=` 取檔名與 `%cI` 時間）。比對寫法 `#N`、`<前綴>N`、`redmine N`，後面不可接數字。squash merge 且訊息沒寫工單號會偵測不到（`none` 就刪舊檔、走一般流程）。結論由分析師的「需求對照表」下，`delta: none|small|full` 決定 dispatch 走捷徑（none 直接待人工交付）；嚴重度條件仍只在協議一處。`reopen` 會把舊的 landed 檔封存。
